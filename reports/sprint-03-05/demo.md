# Запуск и демонстрация

## Окружение

Проверено на Windows x64 с Node.js 26.11.1 и npm 11.20.0. Поддерживаемый минимум — Node.js 22.12, npm 10. Нужен доступ к npm при первом скачивании зависимостей. Docker не требуется. Для браузерных проверок используются установленные Google Chrome и Microsoft Edge.

В корне проекта:

```powershell
npm ci
npm run demo
```

Команда demo применяет миграции, заполняет каталог, проверяет типы, собирает клиент и сервер и запускает приложение. Открыть [Beatstore](http://127.0.0.1:3000). Проверка БД: [health](http://127.0.0.1:3000/api/health). Повторный demo не создаёт дубликаты и не заменяет существующие товары. Остановка — Ctrl+C в терминале запуска.

После первоначальной подготовки достаточно `npm start`. Для разработки: сначала `npm run db:migrate` и `npm run db:seed`, затем `npm run dev`; клиент — [порт 5173](http://127.0.0.1:5173), API — порт 3000. Vite перенаправляет `/api` серверу.

## База и материалы

При отсутствии `DATABASE_URL` автоматически запускается настоящий PostgreSQL 17.10 на `127.0.0.1:55432`. Случайный пароль, кластер и файлы каталога сохраняются в `.local`; эта папка исключена из Git. Локальный кластер останавливается при штатном завершении процесса, который его запустил. Если кластер уже работает, приложение использует его и не останавливает чужой процесс.

На Windows локальный PostgreSQL использует существующие короткие имена 8.3 для путей с кириллицей. Если их создание отключено системой и ASCII-путь недоступен, следует разместить проект в пути латиницей или подключить отдельно установленный PostgreSQL. Приложение не меняет системные настройки.

Для своей БД создать пустую базу PostgreSQL и `.env` по [.env.example](../../.env.example), указав `DATABASE_URL`. Пользователю БД нужны права на создание таблиц, функций и тестовых схем. После этого выполнить те же команды. Параметры `HOST`, `PORT`, `LOCAL_PG_PORT`, `DATA_DIR` описаны в примере. При изменении LOCAL_PG_PORT для нового локального кластера использовать отдельный DATA_DIR. Адрес Vite proxy и конфигурация браузерных проверок по умолчанию рассчитаны на API-порт 3000.

`npm run db:seed` создаёт три бита и два драмкита. WAV, MP3, PNG и ZIP формируются программно из собственных синтетических материалов. Публичны только обложки и шестисекундные демо; исходные комплекты хранятся в private и через публичные маршруты недоступны. Для тестов создаются отдельные схемы БД и временные каталоги, которые удаляются после проверки.

## Сценарий показа преподавателю

1. Запустить проект и открыть главную. Показать пять товаров и переключатели «Все», «Биты», «Драмкиты».
2. Ввести `NIGHT` в поиск. Показать Night Drive; поиск не зависит от регистра. Ввести отсутствующее название и показать пустой результат, затем сбросить поиск.
3. Открыть Night Drive. Показать жанр, BPM, тональность и четыре варианта. Обратить внимание: WAV — только WAV; Trackout — ZIP с WAV-дорожками; Exclusive — ZIP проекта.
4. Включить демо, остановить, перемотать ползунком или клавишами, продолжить. Открыть драмкит и показать один вариант ZIP.
5. Сузить окно до 360 пикселей. Показать доступность поиска, карточки и плеера без горизонтальной прокрутки.
6. Показать `/api/products`, миграцию и результаты тестов: данные приходят из PostgreSQL; основные файлы по прямому публичному адресу не выдаются.
7. Показать отдельные коммиты задач и журнал. Объяснить, какие функции оставлены следующим этапам.

## Краткое объяснение DEV-05

Задача — получить опубликованные товары и карточку из уже подготовленной БД. Контекст для ИИ: схема и тестовые данные предыдущих задач, четыре комплекта бита и один драмкита, публичность только обложек и демо, поиск по названию.

Сначала создан модуль SQL-чтения, который отбирает опубликованные полные товары. Затем результат преобразован в публичный ответ с ценами и адресами демо; внутренние пути исключены. После этого подключены маршруты списка, карточки и публичного файла. Проверка выполнялась через настоящий HTTP-сервер и PostgreSQL. При первой проверке исправлена блокировка обложек из-за скрытой папки `.local`; повтор дал 19 успешных проверок вместе с предыдущими задачами. Результат сохранён коммитом `af1f8c0`, после чего начата DEV-06 — подключение React-интерфейса к готовому API.

## Повторение проверок

```powershell
npm test
npm run build
npm run test:e2e
```

Первая команда проверяет реальные ограничения PostgreSQL, наполнение и HTTP API. Вторая — типы и сборку. Последняя запускает приложение при необходимости и выполняет браузерные сценарии в Chrome и Edge на 360 и 1280 пикселях. HTML-отчёт сохраняется в `playwright-report`, трассировки ошибок — в `test-results`, снимки — в `output/verification`. Команды выполняются последовательно.
