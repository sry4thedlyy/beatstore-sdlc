# Журнал реализации недель 3–5

Работа выполняется по цепочке DEV-01 → DEV-03 → DEV-04 → DEV-05 → DEV-06. Перед каждым шагом фиксируются ожидаемый результат и контекст, затем выполняются изменение, проверка в проекте и коммит рабочего состояния. Реализация следующего шага начинается после проверки предыдущего.

## DEV-01 Окружение и подключение к PostgreSQL

Ожидаемый результат: приложение запускается, использует PostgreSQL и предоставляет проверку работоспособности.

Контекст для ИИ: ТЗ требует PostgreSQL и допускает выбор технологий. UML разделяет веб-интерфейс, серверный REST API и файловое хранилище. На рабочем компьютере имеются Node.js и браузеры Chrome и Edge, но отсутствуют Docker и PostgreSQL.

Решение: TypeScript, Express, React и Vite. Для локальной демонстрации PostgreSQL запускается из закреплённого npm-пакета `embedded-postgres`; отдельная база подключается через `DATABASE_URL`. Пароль локального кластера генерируется и хранится в исключённой из Git папке `.local`. Приложение обращается к базе через `pg`.

Изменения: добавлены конфигурация окружения, жизненный цикл PostgreSQL и HTTP-маршрут `/api/health`. На Windows пути PostgreSQL переводятся в существующие короткие имена 8.3 без изменения системных настроек; база использует UTF-8 и SCRAM, слушает только `127.0.0.1`. Остановка выполняется штатным `pg_ctl`.

Проверка: `npm run typecheck`, `npm run build` и `npm run verify:foundation` выполнены успешно. Последняя команда фактически запустила PostgreSQL 17.10, выполнила SQL-запрос и получила HTTP 200. Проверка повторного запуска также прошла. При первой попытке обнаружена и исправлена несовместимость Windows-кодировки с кириллицей в пути; готовность не объявлялась до успешного запуска.

Дополнительно проверена инициализация нового кластера в отдельном `DATA_DIR=.local/foundation-fresh`: HTTP 200, PostgreSQL 17.10, штатная остановка. Рабочее состояние фиксируется коммитом `feat: bootstrap application and local PostgreSQL` перед переходом к DEV-03.
