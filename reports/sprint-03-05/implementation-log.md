# Журнал реализации недель 3–5

Работа выполняется по цепочке DEV-01 → DEV-03 → DEV-04 → DEV-05 → DEV-06. Перед каждым шагом фиксируются ожидаемый результат и контекст, затем выполняются изменение, проверка в проекте и коммит рабочего состояния. Реализация следующего шага начинается после проверки предыдущего.

## DEV-01 Окружение и подключение к PostgreSQL

Ожидаемый результат: приложение запускается, использует PostgreSQL и предоставляет проверку работоспособности.

Контекст для ИИ: ТЗ требует PostgreSQL и допускает выбор технологий. UML разделяет веб-интерфейс, серверный REST API и файловое хранилище. На рабочем компьютере имеются Node.js и браузеры Chrome и Edge, но отсутствуют Docker и PostgreSQL.

Решение: TypeScript, Express, React и Vite. Для локальной демонстрации PostgreSQL запускается из закреплённого npm-пакета `embedded-postgres`; отдельная база подключается через `DATABASE_URL`. Пароль локального кластера генерируется и хранится в исключённой из Git папке `.local`. Приложение обращается к базе через `pg`.

Изменения: добавлены конфигурация окружения, жизненный цикл PostgreSQL и HTTP-маршрут `/api/health`. На Windows пути PostgreSQL переводятся в существующие короткие имена 8.3 без изменения системных настроек; база использует UTF-8 и SCRAM, слушает только `127.0.0.1`. Остановка выполняется штатным `pg_ctl`.

Проверка: `npm run typecheck`, `npm run build` и `npm run verify:foundation` выполнены успешно. Последняя команда фактически запустила PostgreSQL 17.10, выполнила SQL-запрос и получила HTTP 200. Проверка повторного запуска также прошла. При первой попытке обнаружена и исправлена несовместимость Windows-кодировки с кириллицей в пути; готовность не объявлялась до успешного запуска.

Дополнительно проверена инициализация нового кластера в отдельном `DATA_DIR=.local/foundation-fresh`: HTTP 200, PostgreSQL 17.10, штатная остановка. Рабочее состояние фиксируется коммитом `feat: bootstrap application and local PostgreSQL` перед переходом к DEV-03.

## DEV-03 Модели каталога и миграции

Ожидаемый результат: модели товара, варианта и файла сохраняются в PostgreSQL, деньги хранятся точно, связи не допускают чужие файлы и несовместимые варианты.

Контекст для ИИ: выполненная DEV-01; раздел 5 ТЗ и логическая UML-модель; четыре варианта бита и один вариант драмкита; публичные обложки и демо, защищённые основные файлы; сохранение неизменяемых версий для будущих заказов.

Изменения: добавлены миграция `001_catalog.sql`, исполнитель миграций и типы предметной области. Созданы products, product_files, purchase_variants и variant_files. Составные внешние ключи защищают принадлежность файлов и вариантов, CHECK ограничивает типы и публичность, триггер запрещает изменение сохранённой версии файла. [Физическая схема](../../database/README.md) описана отдельно.

Проверка: `npm run db:migrate` применил схему, `npm test` — 10 успешных проверок на реальном PostgreSQL в изолированной схеме, `npm run build` — успешная сборка. Проверены повтор миграции, точная цена 1490.01, дубликат варианта, недопустимый эксклюзив драмкита, несовпадение типа, связи файлов, запрет публичного основного файла и замены версии, нормализация кириллицы.

Рабочее состояние фиксируется коммитом `feat: model catalog with constraints and migrations` перед подготовкой тестового каталога.

## DEV-04 Воспроизводимый тестовый каталог

Ожидаемый результат: три бита и два драмкита с обложками, демо, ценами и полными комплектами; повторное заполнение не создаёт дубликатов.

Контекст для ИИ: готовая миграция DEV-03 и связи файлов с вариантами; заданные пользователем комплекты MP3, WAV, ZIP дорожек и ZIP проекта; отсутствие предоставленных музыкальных исходников. Условия коммерческих лицензий относятся к будущей DEV-18.

Изменения: добавлен детерминированный генератор собственных синтетических WAV, MP3 и PNG, ZIP с дорожками и учебными проектами. ZIP проекта содержит project.json и исходные WAV, а не имитацию файла закрытой DAW. Материалы сохраняются в `.local/storage`; приложение будет выдавать публично только обложки и демо. Заполнение выполняется одной транзакцией, использует устойчивые идентификаторы, не меняет существующие записи и не перезаписывает другую версию файла.

Проверка: `npm run db:seed` создал 3 бита и 2 драмкита; `npm test` — 13 успешных проверок, включая 14 вариантов, 24 файла, повторное заполнение, SHA-256, WAV/MP3 и содержимое обоих видов ZIP. `npm run build` прошла успешно. Аудиоматериалы учебные; реальные лицензии и покупки на этом этапе не формируются.

Рабочее состояние фиксируется коммитом `feat: seed reproducible catalog and original demo assets` перед реализацией API.

## DEV-05 Чтение каталога и публичные материалы

Ожидаемый результат: список, поиск по названию, карточка, варианты и цены доступны через HTTP; защищённые пути и основные файлы не выдаются.

Контекст для ИИ: проверенные DEV-01, DEV-03, DEV-04; схема PostgreSQL, назначение публичных и защищённых файлов, ограничения ТЗ на публикацию полного товара. Поиск должен работать с кириллицей независимо от локали PostgreSQL.

Изменения: добавлены параметризованные SQL-запросы, общие типы ответов, маршруты каталога и карточки, выдача публичных файлов с Range. Из чтения исключаются черновики, архивные товары и товары с неполными или несовместимыми комплектами. Путь проверяется после realpath; основные файлы и внутренние метаданные не попадают в ответы. [Контракт API](api.md) записан отдельно.

Проверка: 19 тестов на PostgreSQL и реальном HTTP прошли; сборка успешна. Проверены количество и типы товаров, поиск на русском, буквальное значение SQL-символов, неверные параметры, цены, скрытые товары, форматы PNG/WAV, Range и запрет прямого доступа к основным файлам и конфигурации. Первая проверка обнаружила блокировку публичных файлов из-за скрытого родительского каталога `.local`; исправлена выдача относительно явно заданного корня, повтор прошёл.

Рабочее состояние фиксируется коммитом `feat: expose published catalog and public previews` перед подключением интерфейса.

## DEV-06 Интерфейс и первый пользовательский сценарий

Ожидаемый результат: посетитель получает каталог из PostgreSQL, ищет товар, открывает карточку, видит варианты и слушает демо; обработаны загрузка, пустой результат и ошибка. Интерфейс работает на ширинах 360 и 1280 пикселей.

Контекст для ИИ: проверенный контракт API DEV-05, реальные пять товаров и публичные материалы DEV-04, общие TypeScript-типы и ограничения текущего этапа. Покупки, авторизация и лицензии ещё не реализованы, поэтому интерфейс показывает только доступные действия.

Изменения: добавлены React-компоненты каталога и карточки, поиск с отменой устаревших запросов, фильтр типа, состояния загрузки и повтора, единый аудиоплеер с паузой и перемоткой. Vite собирает интерфейс; Express выдаёт сборку на одном адресе с API и поддерживает прямое открытие карточки. Команды setup/demo разворачивают текущий сценарий. Проверка типов охватывает клиент, сервер, сценарии и тесты.

Проверка: сборка и 19 проверок PostgreSQL/API прошли; 24 браузерные проверки прошли в Chrome и Edge при 360 и 1280 пикселях. Проверено реальное декодирование и изменение времени аудио, пауза, перемотка мышью и клавишами, смена демо, поиск и фильтры, пустой результат, ошибка с повтором, загрузка, карточки по прямому адресу и отсутствие горизонтального переполнения. Скриншоты каталога и карточки просмотрены визуально.

Обнаруженная проблема: исходная обработка изменения range не передавала новую позицию аудио. Повторная проверка с клавиатурой подтвердила ошибку интерфейса. Исправлено на событие input с синхронизацией позиции; после этого отдельно прошёл тест плеера во всех четырёх конфигурациях, затем весь набор.

Рабочее состояние фиксируется коммитом `feat: implement catalog interface and audio preview` после успешных проверок, перед итоговой подготовкой материалов.
