# Недели 3–5. Базовая реализация

Поладов Михаил Заурович, ПИ 31/1.

## Полученный результат

Создана запускаемая основа Beatstore: React-интерфейс, Express API, PostgreSQL и файловое хранилище. Работает первый пользовательский сценарий: посетитель открывает каталог, находит товар по названию, переходит в карточку, видит варианты с ценами и слушает демо.

Выполнена последовательность из декомпозиции второго спринта: **DEV-01 → DEV-03 → DEV-04 → DEV-05 → DEV-06**. Реализованы пять товаров: три бита и два драмкита, 14 вариантов приобретения и 24 файла. Обложки и аудио генерируются воспроизводимо; сторонние музыкальные материалы не требуются.

| Требование этапа | Реализация и подтверждение |
| --- | --- |
| Основная структура | `src/client`, `src/server`, `src/shared`, `database`, `scripts`, `tests`. |

## Что изменилось в проектных решениях

Выбран стек TypeScript / Express / React / Vite и драйвер `pg`. PostgreSQL сохранён согласно ТЗ. Для локального запуска добавлена поставка PostgreSQL через npm-пакет; установленную отдельно БД можно подключить через `DATABASE_URL`. Секреты и данные хранятся вне Git.

Логическая модель конкретизирована в [физической схеме каталога](../../database/README.md). Денежные суммы хранятся как `numeric(12,2)`, файлы имеют неизменяемые версии, публичные материалы отделены от основных. Созданы [контракт API](api.md) и команды развёртывания. Эти решения укладываются в ТЗ; бизнес-правила и актуальные Word/PDF не менялись. UML описывает проект целиком, физическая схема — реализованную часть.

Учебный ZIP проекта содержит `project.json` и исходные WAV-дорожки. Он демонстрирует согласованный комплект Exclusive; совместимость с форматом конкретной DAW не заявляется. Тексты коммерческих лицензий ещё не подготовлены, выдача покупки отсутствует.

## Границы этапа и продолжение

Не реализованы учётные записи, административное редактирование, заказы, ЮKassa, эксклюзивная продажа, PDF-лицензии, история и защищённое скачивание после покупки. Интерфейс показывает фактически доступные просмотр и прослушивание. Это соответствует объёму недель 3–5: работающая основа и часть сценария, без требования завершить всю обязательную функциональность.

Следующий порядок: DEV-02 → DEV-07 → DEV-08 → DEV-09; затем DEV-10 и DEV-18 → DEV-11. После этого можно переходить к заказам и оплате с учётом зависимостей. Все 27 задач и их статусы остаются в [декомпозиции](../sprint-02/development-tasks.md).
