# База данных каталога

Реализованная часть логической модели: товар, вариант приобретения и неизменяемая версия файла. Связь варианта с файлами хранится отдельно. PostgreSQL — единственная используемая СУБД; SQLite или данные в памяти не заменяют базу.

| Таблица | Назначение |
| --- | --- |
| products | Название, описание, тип товара, состояние публикации, характеристики бита, ссылки на обложку и демо. Поле title_search хранит нормализованное имя для одинакового поиска на Windows и Linux. |
| product_files | Версии файлов, владелец-товар, назначение, публичность, внутренний ключ хранения, MIME-тип, размер и SHA-256. Изменение версии на месте запрещено триггером. |
| purchase_variants | Варианты товара, точная цена numeric(12,2) в RUB, текст и версии условий и шаблона. Для бита допустимы MP3, WAV, Trackout и Exclusive, для драмкита — только drumkit. |
| variant_files | Связь варианта с основными файлами. Составные внешние ключи не допускают файл чужого товара или публичную обложку вместо основного файла. |
| schema_migrations | Применённые миграции и контрольные суммы. Повторный запуск не применяет SQL заново; изменение применённой миграции обнаруживается. |

```powershell
npm run db:migrate
npm test
```

Миграции применяются одной транзакцией под блокировкой. Проверки создают отдельную схему `verification_<случайный идентификатор>` и удаляют только её; таблицы рабочего каталога не используются для тестовых записей.

Пользователи, заказы, платежи и лицензии остаются частью [планируемой UML-модели](../diagrams/README.md). Их реализация относится к следующим задачам. Физическая схема каталога не меняет правил ТЗ.
