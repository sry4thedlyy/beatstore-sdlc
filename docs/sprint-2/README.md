## Изменения существующих диаграмм

| Диаграмма прошлого семестра | Изменения для нового ТЗ |
| --- | --- |
| Компоненты | Сохранены веб-интерфейс, сервер, REST API и PostgreSQL. Добавлены тестовая ЮKassa, файловое хранилище и шаблоны лицензий; разделены публичные и защищённые файлы. Уточнено, что серверные модули входят в одно приложение. |
| Регистрация | Убрана обязательная отправка письма. Добавлены проверка данных, хеширование пароля, назначение роли покупателя сервером и защита уникальности email, в том числе при одновременных запросах. |
| Покупка товара | Добавлены выбор варианта, серверная цена, снимок заказа и правила эксклюзива. Оформление и подтверждение оплаты вынесены в две диаграммы. Учтены неизвестный результат запроса, повторное уведомление и независимость успешной оплаты от ошибки PDF. |
| Скачивание | Уточнены проверка владельца, оплаты и принадлежности файла зафиксированному комплекту. Проверки выполняются при выдаче и открытии временной ссылки. Прямой доступ к защищённому хранилищу закрыт. |
| Добавление товара | Добавлены проверка роли, типов и размеров файлов, черновик, проверка полноты вариантов и публикация. Зафиксировано сохранение версий файлов ожидающих и оплаченных заказов. |

В предоставленном отчёте диаграммы содержались как изображения. Их логика и состав участников использованы для актуализации; подготовлены новые текстовые исходники PlantUML. [Первоначальный отчёт](../previous-semester/uml-original.docx) сохранён для сравнения.

Дополнительно подготовлены обзор вариантов использования и логическая модель данных. Они показывают обязательные функции трёх ролей и связи семи основных понятий ТЗ. Эти диаграммы дополняют существующие материалы.

## Проверка согласованности

- Корзина, аналитика, управление пользователями и обязательный email-сервис отсутствуют в актуальных диаграммах и задачах.
- У бита четыре варианта: MP3-файл, WAV-файл, ZIP с WAV-дорожками, ZIP проекта. У драмкита один вариант с архивом. Условия и цена задаются для варианта.
- Один заказ связан с одним покупателем и одним вариантом; история сохраняет собственные условия и версии файлов.
- Платёж может ещё не быть создан; номер лицензии существует независимо от готовности PDF. Неизвестный результат оплаты сохраняет ожидание, повторное подтверждение не создаёт дубликатов.
- Лизинг допускает параллельные заказы; эксклюзивная покупка согласуется с незавершёнными оплатами и после успеха запрещает новые заказы. Прежние покупки сохраняются.
- Матрица соответствия покрывает FR-01–FR-12, NFR-01–NFR-04 и раздел 5. Для обязательных функций определены задачи, для каждой зависимости указан существующий идентификатор; циклических зависимостей нет.

Проверка относится к проектной документации. Фактическая работа приложения, интеграция ЮKassa и выполнение критериев приёмки проверяются после реализации соответствующих задач. Требования ТЗ в ходе второго спринта не изменены.

## Начало реализации

Ближайшая последовательность: DEV-01 → DEV-03 → DEV-04 → DEV-05 → DEV-06. Она даёт запускаемое приложение с каталогом из PostgreSQL, поиском, карточкой и демо. Учётные записи можно развивать после подготовки окружения. Полный перечень задач определяет зависимости дальнейшей покупки, оплаты и выдачи файлов; календарный план всего семестра не устанавливается.
